# 对接现有测试工具

本包不提供 benchmark 请求执行器，也不依赖某台电脑上的私有工具。计划与报告流程可以独立使用；执行真实请求需要用户提供或选择一个可用工具。

## 先确定能力，不猜命令

记录工具的公开来源或用户提供的目录、版本/commit、安装要求、README 和 CLI 帮助。读取帮助前判断入口是否会执行网络初始化。

| 能力 | 核对要求 |
| --- | --- |
| 协议 | 目标 API 版本、模型和流式事件能被正确处理 |
| 凭据 | 从环境变量或受控凭据源读取，不进入可共享配置 |
| 无网络预检 | 文档或实现能证明配置检查不会发送真实请求 |
| 停止边界 | 有请求数、并发、超时、重试上限及可执行的预算控制 |
| 观测 | 保存首字节、首语义增量、首 content、完成时间和错误 |
| 证据 | 失败样本、usage、配置快照和工具版本可追溯 |
| 离线分析 | 从既有结果复算，或读取结果后独立计算 |

没有可用执行器时，交付计划、输入缺口和工具能力要求；不拼出未验证的命令，也不为了证明可用而发送试探性生成请求。

## 模板的使用边界

`assets/provider-config-template.json` 和 `assets/profile-template.json` 是本包定义的**信息交换示例**，不是第三方工具可直接读取的配置。它们不包含凭据，不授权执行。

1. 按任务填写供应商、模型、矩阵和预算。
2. 根据已核对工具的实际 schema 映射字段。
3. 未映射字段列为缺口，不忽略并发、重试、费用或输出上限。
4. 用已证实无网络的模式，或离线 JSON/schema 检查验证配置。
5. 在已有实际执行授权且边界明确后，才运行真实请求入口。

若没有硬费用上限，使用已核对价格、输入/输出上限、请求上限、预热与重试上限计算保守预算；价格或计费单位不明时，不声称能遵守金额上限。

## 建议证据结构

名称可以适配工具，信息不可省略：

- manifest：工具版本、测试矩阵、时间、预算和授权摘要。
- raw：已脱敏请求/响应、事件时间、usage 和失败记录。
- normalized：统一单位、有效样本、缺失原因、计算结果。
- report：事实、推断、未测试项和证据链接。

这是交付约定，不是某个 CLI 的实际输出承诺。原始业务结果保留在用户指定的本地位置，对外副本另行脱敏。

复核请求数能对齐计划和实际运行、分位数算法可追溯、流式缺少 usage 不被误算为缓存未命中、复测结果没有覆盖原批次。工具测试通过不能作为供应商性能结论。
