# 指标与证据口径

生成或复核报告时读取。

## TTFT

- 仅流式请求有 TTFT。
- 起点为请求发出；终点为第一个非空 reasoning 或 content 语义增量。
- 首字节、首 SSE 事件、首 reasoning、首 content 分开保存；不要把首字节直接叫 TTFT。
- HTTP 2xx 但没有语义增量时，TTFT 无效；不能用总耗时代替。
- 非流式请求属于口径外，不算 TTFT 缺失样本。

报告至少给出有效样本数、缺失样本数及原因、P50/P90/P95/P99、最小/最大值和测试输入/并发。分位数算法由工具决定，但必须在报告中可追溯。少量样本的高分位数只能作为探索性结果，不据此宣称服务稳定性。

## 错误率

分开报告：

- **全局错误率**：全部正式请求中的失败比例，不含配置 dry-run/preflight。
- **TTFT 错误率**：仅 TTFT eligible 请求中的失败比例。

不要用“HTTP 200 比例”替代模型输出完整性、流式语义或缓存可统计性。

## 缓存

先确认字段语义：

- `includes_cache`：输入 Token 已包含 cached tokens；分母直接使用输入 Token。
- `excludes_cache`：输入 Token 不含 cache creation/read；分母需要相加得到逻辑输入。
- `unknown`：保留字段和警告，精确 Token 命中率输出 N/A。

至少区分：请求命中率、Token 加权命中率、缓存创建 Token、缓存读取 Token、冷启动与预热。若工具使用冷启动基线判断目标前缀命中，应同时报告基线和增量，不能仅凭 `cache_read > 0` 宣称本轮目标前缀命中。

流式缓存请求缺少 usage 时，TTFT 可以有效，但缓存指标不可统计。

## 性能矩阵

计划中固定：

- 协议与流式模式；
- 输入长度、输出上限、并发、样本数；
- 推理强度/思考开关；
- 冷启动、预热和唯一前缀策略；
- 超时、重试、失败处理；
- 预算与停止阈值。

测试中途修改任一项时，开启新批次或在 manifest 中标记，避免把不同条件混在同一分位数中。

## 证据状态

- **已验证**：有 manifest、原始记录、规范化数据和可复算结论。
- **部分验证**：请求成功，但 usage、流式事件或样本不足。
- **失败**：实际请求失败或指标不满足预设标准。
- **未测试**：没有执行该项。
- **证据不足**：有结果但缺关键原始证据，无法可靠计算。
- **不适用**：模型或协议明确没有该能力；不要当作失败，也不要强行计入完整性评分。

## 复测原则

- 对异常值、协议错误和 0%/100% 缓存等强结论复测；
- 不删除失败请求或只挑最好批次；
- 复测结果与原结果同时保留，并说明哪一批用于最终结论；
- 工具单元测试通过只证明测试工具行为，不证明供应商性能。
