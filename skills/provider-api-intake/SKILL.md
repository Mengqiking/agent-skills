# Provider API Intake

把“资料是否完整、协议是否匹配、能否做免费连通性检查、何时才允许真实推理”一次说明白，并留下可复核材料。

## 先选择工作模式

- **准备模式**：阅读文档、检查 URL/鉴权/schema，生成命令、Postman 或评审结论；不访问供应商。
- **免费连通模式**：仅执行有证据表明不计费且不创建资源的 DNS/TLS、健康检查、模型列表或只读查询。
- **正式实测模式**：会调用推理、生成、上传、创建任务或其他可能计费/写入的接口。只有用户在当前任务中明确要求实际执行，并且范围与预算清楚时才能运行。

生成可直接执行的命令或 Postman Collection 不等于实际调用，不要为生成物增加人为阻断开关。实际执行前仍按上述模式判断授权。

## 工作流

1. 读取 [references/intake-fields.md](references/intake-fields.md)，建立接入事实表；缺失项标为“未知”，不要猜。
2. 证据优先级：当前实测响应 > 当前供应商文档 > 上游官方文档 > 经验推测。用户明确指定的供应商名称、模型名和输出命名优先于网页标题。
3. 对时间敏感的协议、端点、模型能力和价格，查当前官方文档；区分供应商兼容声明与上游原生能力。
4. 先做静态检查，再决定是否存在安全的免费连通路径。若无法证明免费，停止实际调用，只交付命令/Collection 和待确认项。
5. 生成 curl/Postman 时：
   - 用户本会话提供了凭据且要求可直接执行时，按其要求原样填入；最终说明和报告不得复述完整值。
   - Collection 变量只是集中存放，真实值仍会保存在文件中，不能当作脱敏。含真实凭据的可执行资产必须写到仓库外或已验证被忽略的目录；受 Git 跟踪的模板只能留空或引用环境变量，不能把 Key 藏进 Collection 变量。
   - 当前任务已明确授权使用真实凭据且输出位置符合上述边界时直接继续，不要重复询问；只有目标会被跟踪、忽略状态不明或授权范围变化时才停下确认。
   - Postman 通过目录和请求名标注“只读”“可能计费”“写操作”“危险操作”。生成物的运行方式遵循用户要求；不要建议未经逐项审阅就一键运行整套 Collection。
6. 免费连通性只记录方法、脱敏 URL、状态码、顶层字段、鉴权结果和时间；不得用一次生成请求冒充“连通性测试”。
7. 输出 GO / NO-GO / 待补资料，逐项说明证据、未验证项、计费/写入风险和下一步。

## 扩展与协作

- 供应商专用路径、模型名、状态枚举与验收条件应来自当前官方文档或用户提供的资料，不把其他供应商的约定复制过来。
- 需要正式测 TTFT、缓存命中、吞吐量或生成性能报告时，如果已安装 `model-benchmark-report`，使用该 Skill；否则先交付测试计划和缺失能力，不假装已经执行性能测试。

可从 [assets/provider-intake-report-template.md](assets/provider-intake-report-template.md) 复制并裁剪交付结构。

## 停止条件

- 只有推理/生成接口可验证，或免费性无法确认。
- 鉴权、协议版本、实际模型 ID、计费规则或目标环境不明确。
- 请求可能修改生产数据、创建资源或命中非目标渠道。
- 结论只能来自 HTTP 200、字段名、域名外观或用户截图，缺少终态/产物/日志证据。

停止时继续完成不产生外部副作用的资料核对、命令生成和缺口清单，不把“未验证”写成“不可用”。
