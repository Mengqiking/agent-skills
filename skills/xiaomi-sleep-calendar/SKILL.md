# 小米睡眠补录到 Google 日历

## 先查缺口

1. 使用 Google Calendar 连接器，查询目标日历和时区。用户要求“最近”但未给日期时，先查最近 14 天，并说明最终核对范围。跨午夜时把查询窗口向前留至少一天。查看最近几条睡眠事件作为模板，提取标题、颜色、可见性、忙闲状态、提醒和事件标签。如有命名标签，通过连接器读取并按名称解析。
2. 翻完查询窗口内的分页，合并标题命中和标签匹配的事件，按当地**醒来日期**找缺口。保留已有事件。发现同一天有多个候选或仅有小睡时，以时间段和描述判断是否已有夜间记录。只有缺失时才继续读取对应日期。当天只写已生成的完整记录。

## 只读缺失日期

3. 若本次已有可信的结构化睡眠来源，优先读取该来源。否则打开小米运动健康的睡眠日视图，按[手机镜像速查](references/phone-mirror.md)读取。每个日期只记录夜间入睡与醒来、实际睡眠时长、小睡起止与时长、数据来源。若卡片展示的是全天总时长，优先取睡眠详情里的分段时长。若明确只含一次夜间睡眠及已核对的所有小睡，可用全天总时长减去小睡时长计算实际夜间时长。日历事件使用时间轴的准确端点。
4. 如果标题模板含天气，依据用户指定或能从任务确认的城市，一次查齐所需日期的历史天气和最低、最高温。沿用最近的标题格式。若缺少天气或主观评分的依据，保留可核验字段并在结果简述缺项。遇到无记录或图表端点不可辨的日期，先处理其余日期。

## 批量写入并回读

5. 写入前针对目标日历和已读取的日期复查查重，尤其是用户可能同时操作或连接器响应曾超时的情况。按近期同类记录建立日程。若模板将小睡放在标题和备注，继续以一个夜间事件承载该日记录。为用户自己的睡眠事件保留原有私人设置，不添加参与人或会议。
6. 批量处理不同日期。每条按创建、记录事件 ID、添加已解析的标签、回读验证的顺序运行。创建结果不明确时按日期和区间查找已落地的事件，确认缺失后才重试。标签失败时按已有事件 ID 补标签。
7. 批量回读核对日期、入睡与醒来、标题、小睡备注和标签。汇报已补、原有和仍有缺口的日期，并提供日历链接。做过回读的记录才计入已完成。
